## 🔧 PROBLÈMES RÉSOLUS

### 1. Conversion VARCHAR → TIMESTAMP
**Problème** : Colonnes de dates stockées en VARCHAR dans RAW  
**Solution** : Utilisation de `try_to_timestamp()` au lieu de `::timestamp`  
**Fichiers affectés** : stg_orders.sql, stg_reviews.sql  

### 2. Conversion FLOAT → INT
**Problème** : Dimensions produits en FLOAT, besoin d'INT  
**Solution** : `round(column)::int` au lieu de `column::int`  
**Fichiers affectés** : stg_products.sql  

### 3. Typo dans dataset Olist
**Problème** : Colonnes nommées `product_name_lenght` (typo: "lenght")  
**Solution** : Utilisation du nom exact avec typo  
**Fichiers affectés** : stg_products.sql  

### 4. Duplicatas review_id
**Problème** : 789 review_id en doublon dans RAW_REVIEWS  
**Solution** : Déduplication avec `QUALIFY ROW_NUMBER()`  
**Impact** : 99,224 → 98,435 rows (-789 rows)  

### 5. Duplicatas geolocation
**Problème** : 1M de lignes pour ~20K zip_codes  
**Solution** : Déduplication avec `QUALIFY ROW_NUMBER()`  
**Impact** : 1,000,163 → 19,015 rows (-98%)

## 🎓 APPRENTISSAGES CLÉS

### Techniques DBT

1. **Déduplication avec QUALIFY** : Pattern réutilisable
   ```sql
   qualify row_number() over (partition by key order by date desc) = 1
   ```

2. **try_to_timestamp()** : Meilleur que `::timestamp` pour VARCHAR
3. **round()::int** : Meilleur que `::int` direct pour FLOAT
4. **Tests relationships** : Valident l'intégrité référentielle
5. **accepted_values** : Valident les enum/statuts

### Patterns SQL Snowflake

- CTEs bien organisés (source → renamed → deduplicated)

- Casting explicite des types
