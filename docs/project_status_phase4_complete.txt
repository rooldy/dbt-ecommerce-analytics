## 🎯 OBJECTIF DU PROJET

### Vision globale

Créer un **pipeline de données production-ready** pour analyser les données e-commerce du dataset Olist (marketplace brésilien), en utilisant la stack moderne **DBT + Snowflake**, et en suivant les meilleures pratiques de l'industrie.

### Objectifs SMART

1. **Infrastructure moderne** : Data warehouse Snowflake + transformations DBT
2. **Modèles analytiques métier** : 40+ modèles (staging, intermediate, marts)
3. **Qualité garantie** : >90% de couverture de tests
4. **Star Schema** : Modèle dimensionnel pour BI
5. **Visualisation** : 4 dashboards opérationnels
6. **Optimisation** : Coûts <5$ USD, performance <5min build
7. **Portfolio** : Projet démontrant compétences Analytics Engineer

### Pourquoi ce projet ?

**Contexte professionnel** : Préparation pour une offre d'emploi Analytics Engineer mentionnant DBT et Snowflake.

**Compétences ciblées** :
- ✅ Modélisation et architecture Snowflake optimisée
- ✅ Ingestion de données robuste
- ✅ Star Schema et modélisation dimensionnelle
- ✅ Optimisation des coûts et performances
- ✅ Tests et qualité des données
- ✅ Documentation professionnelle
- ✅ Partage de connaissances

## 📊 ARCHITECTURE DU PROJET

| Composant | Technologie | Version |

### Architecture des données (Medallion + Star Schema)

```
CSV Files (Kaggle)
    ↓
RAW (Bronze) - 9 tables, 1.5M+ rows
    ↓
STAGING (Silver) - Nettoyage, standardisation (9 models)
    ↓
INTERMEDIATE (Silver) - Logique métier (3 models)
    ↓
MARTS_CORE (Gold) - Star schema (2 facts + 5 dimensions)
    ↓
MARTS_ANALYTICS (Gold) - KPIs métier (à venir)
    ↓
Dashboards BI
```

### Snowflake - Configuration

```
DATABASE: DBT_ECOMMERCE
├── SCHEMA: RAW (9 tables - 1.5M rows)
├── SCHEMA: STAGING_STAGING (9 models)

└── SCHEMA: MARTS_ANALYTICS (à venir)
```

**Exemple de requête Star Schema** :
```sql
-- Revenue par customer tier et trimestre
SELECT 
    c.customer_tier,
    d.year_quarter,
    COUNT(DISTINCT f.order_id) as orders,
    SUM(f.total_payment_value) as revenue
FROM marts_core.fct_orders f
JOIN marts_core.dim_customers c ON f.customer_key = c.customer_key
JOIN marts_core.dim_date d ON f.order_date_key = d.date_key
WHERE f.is_delivered = 1
GROUP BY c.customer_tier, d.year_quarter;
```

⚠️ **DBT** :

- `dbt debug` pour tester connexion avant de travailler
- `dbt deps` après modification de packages.yml

⚠️ **Matérialisation** :
- Staging/Intermediate : VIEW (économie stockage)
- Marts : TABLE (performance requêtes)
- Incremental : Pour grandes tables temporelles (Phase 5)

### Problèmes résolus et solutions

**1. Erreur : "Certificate validation failed"**
- ✅ Solution : Ajouter `'insecure_mode': True` dans SNOWFLAKE_CONFIG

**2. Erreur : "dbt_project.yml not found"**
- ✅ Solution : Être dans le dossier dbt_ecommerce/

**3. Erreur : "Source not found"**
- ✅ Solution : Vérifier _sources.yml, vérifier que tables existent dans Snowflake

**4. Schémas avec préfixe (STAGING_STAGING au lieu de STAGING)**
- ✅ Solution : Macro generate_schema_name.sql créée

**5. VARCHAR → TIMESTAMP conversion**
- ✅ Solution : try_to_timestamp() au lieu de ::timestamp

**6. FLOAT → INT conversion**
- ✅ Solution : round() puis ::int

**7. Duplicatas dans reviews et geolocation**
- ✅ Solution : QUALIFY ROW_NUMBER() avec partition by
