## 🎯 OBJECTIF DU PROJET

### Vision globale

Créer un **pipeline de données production-ready** pour analyser les données e-commerce du dataset Olist (marketplace brésilien), en utilisant la stack moderne **DBT + Snowflake**, et en suivant les meilleures pratiques de l'industrie.

### Objectifs SMART

1. ✅ **Infrastructure moderne** : Data warehouse Snowflake + transformations DBT
2. ✅ **Modèles analytiques métier** : 24 modèles (staging, intermediate, marts)
3. ✅ **Qualité garantie** : >90% de couverture de tests (224 tests, 100% succès)
4. ✅ **Star Schema** : Modèle dimensionnel pour BI
5. ✅ **Marts Analytics** : KPIs pré-calculés (CLV, cohorts, rankings)
6. ⏳ **Visualisation** : 4 dashboards opérationnels (à venir)
7. ✅ **Optimisation** : Coûts <5$ USD, performance <5min build
8. ✅ **Portfolio** : Projet démontrant compétences Analytics Engineer

### PHASE 5 : MARTS ANALYTICS (COMPLÉTÉE ✅)

**Durée** : 1 heure (19 janvier 2025, 20h25-21h30) ⚡⚡

**Objectif** : Créer des marts analytiques avec KPIs pré-calculés

**Modèles créés (6/6)** :

#### 1. `mart_sales_daily.sql` ⭐ INCREMENTAL

**Type** : INCREMENTAL (première utilisation !)

**Responsabilité** : Ventes quotidiennes agrégées

**Métriques** :
- Orders, revenue, AOV par jour
- Unique customers, items sold
- Payment methods breakdown
- Delivery metrics (avg days, on-time rate)
- Cancellation rate

**Features avancées** :
- **Incremental materialization** : Ajoute seulement les nouvelles dates
- **Moving averages** : 7-day MA pour revenue et orders
- **YoY comparisons** : lag(365) pour comparer année précédente
- **Weekend/Holiday flags** : Analyse des patterns temporels

**Configuration** :
```sql
config(
    materialized='incremental',
    unique_key='date_key',
    on_schema_change='fail'
)
```

**Grain** : 1 ligne par jour (851 lignes pour 2016-2018)

**Utilité** :
- Dashboards de ventes quotidiennes
- Détection de tendances
- Calculs MTD, QTD, YTD
- Impact des week-ends et jours fériés

#### 2. `mart_customer_lifetime_value.sql`

**Responsabilité** : CLV prédictif et segmentation avancée

**Métriques calculées** :
- `historical_ltv` : Valeur lifetime réelle
- `predicted_clv_12m` : CLV prédit sur 12 mois (modèle simplifié)
- `engagement_score` : Score 0-100 basé sur activité
- `lifetime_months` : Âge du client en mois
- `avg_days_between_orders` : Fréquence d'achat

**Segmentations** :
- **CLV Tier** : Very High, High, Medium, Low, Very Low
- **Churn Risk** : Very High, High, Medium, Low-Medium, Low
- **Marketing Priority** : URGENT, HIGH, MEDIUM, LOW avec actions recommandées

**Logique de prédiction CLV** :
```sql
Active + Repeat → AOV × (orders_per_month × 12)
Active + One-time → AOV × 2
At Risk → AOV × (orders_per_month × 6)
Dormant → AOV × 1
Lost → 0
```

**Exemples de marketing_priority** :
- "URGENT - Retain VIP" : VIP at risk ou dormant
- "HIGH - Win Back" : Gold/Silver at risk
- "MEDIUM - Convert to Repeat" : Bronze active one-timer
- "HIGH - Nurture High Value" : Active avec CLV prédit >1000

**Utilité** :
- Budgets marketing par segment
- Priorisation rétention
- ROI campagnes
- Prédiction churn

#### 3. `mart_product_performance.sql`

**Responsabilité** : Performance produits avec reviews et rankings

**Métriques** :
- Sales : orders, units_sold, revenue
- Reviews : count, avg_rating, satisfaction_rate
- Pricing : avg_price, min/max
- Freight : freight_cost_pct

**Features avancées** :
- **Rankings multiples** :
  - rank_in_category_revenue
  - rank_in_category_units
  - rank_in_category_rating
  - rank_overall_revenue

- **Product Health Score** (0-100) :
  - Sales component (40 pts) : Basé sur percentile revenue
  - Rating component (40 pts) : Basé sur avg_rating
  - Review engagement (20 pts) : Basé sur review_rate

- **Revenue Tiers** : Top 10%, Top 25%, Top 50%, Bottom 50%

- **Product Recommendations** :
  - "Feature Product" : Top 10% + rating ≥ 4.5
  - "Consider Removal" : rating < 3.0 avec assez de reviews
  - "Investigate Quality" : Top revenue mais satisfaction < 70%
  - "Category Leader" : Top 3 dans catégorie
  - "High Cost + Low Satisfaction" : Freight > 30% + rating < 4.0

**Utilité** :
- Optimisation catalogue
- Identification best/worst sellers
- Corrélation prix/satisfaction
- Décisions merchandising

#### 4. `mart_delivery_kpis.sql`

**Responsabilité** : KPIs logistiques par route (customer_state × seller_region)

**Métriques delivery** :
- avg_delivery_days, median, P90
- avg_estimated_days vs actual
- avg_delay_days
- Breakdown : days_to_carrier, days_carrier_to_customer

**Performance metrics** :
- on_time_rate (%)
- late_delivery_rate (%)
- SLA compliance (5-day, 10-day)

**Scores** :
- **Reliability Score** (0-100) :
  - On-time component (60 pts)
  - Consistency component (40 pts) - pénalise variance

- **Delivery Efficiency** : (estimated / actual) × 100

**Classifications** :
- **Performance Tier** : Excellent, Good, Fair, Needs Improvement
- **Primary Issue** : High Late Delivery, Slow Delivery, Inconsistent, Chronic Delays
- **Recommendations** : Actions spécifiques par problème

**Utilité** :
- SLA monitoring
- Optimisation routes logistiques
- Identification corridors problématiques
- Choix des carriers

#### 5. `mart_customer_cohorts.sql`

**Responsabilité** : Analyse de rétention par cohorte mensuelle

**Grain** : 1 ligne par (cohort_month × months_since_cohort)

**Métriques** :
- `cohort_size` : Nombre de clients acquis ce mois
- `active_customers` : Actifs à ce stade
- `retention_rate` : % de rétention
- `cohort_revenue` : Revenue du mois
- `cumulative_revenue` : Revenue cumulé depuis acquisition
- `cumulative_revenue_per_customer` : CLV cumulatif

**Features avancées** :
- **Cohort Health** : 
  - New Cohort (M0)
  - Healthy/At Risk (M1-3)
  - Stable/Weak (M4-6)
  - Mature Good/Poor (M7-12)
  - Long-term Loyal/Churned (M13+)

- **Projected LTV** : Extrapolation à 24 mois si cohorte ≥ 6 mois

- **Retention Drop** : Différence avec mois précédent

- **Cohort Age Groups** :
  - M0 - Acquisition
  - M1-3 - Early Engagement
  - M4-6 - Growth
  - M7-12 - Maturity
  - M13+ - Long-term

**Utilité** :
- Mesurer rétention mois par mois
- Identifier cohortes performantes
- Calculer payback period
- Benchmarks acquisition

#### 6. `mart_sales_by_category.sql`

**Responsabilité** : Performance par catégorie avec growth metrics

**Grain** : 1 ligne par (category × year × month)

**Métriques** :
- Volume : orders, units_sold, unique_customers
- Revenue : product_revenue, freight_revenue, total_revenue
- Per-unit : revenue_per_unit, units_per_order
- Freight : freight_cost_ratio

**Growth metrics** :
- **MoM Growth** : Month-over-month revenue et units
- **YoY Growth** : Year-over-year comparisons
- **Share metrics** : % du revenue/units total du mois
- **Moving averages** : 3-month MA

**Rankings** :
- rank_in_month_revenue
- rank_in_quarter_revenue
- rank_overall_revenue (basé sur total catégorie)

**Classifications** :
- **Performance Tier** : Top Tier (≥10%), High (≥5%), Mid (≥2%), Low (<2%)
- **Growth Status** : High Growth (≥20%), Growing (≥5%), Stable (±5%), Declining, Sharp Decline
- **Strategic Category** (BCG Matrix) :
  - "Star - Invest" : Share ≥10% + Growth ≥5%
  - "Cash Cow - Maintain" : Share ≥10% + Growth <5%
  - "Rising Star - Grow" : Share <5% + Growth ≥10%
  - "Question Mark - Review" : Share <2% + Growth <0%
  - "Core - Monitor" : Autres

**Utilité** :
- Mix produit optimal
- Stratégie pricing
- Tendances consommation
- Décisions portfolio

## 🚀 CAS D'USAGE BUSINESS

### Executive Dashboard

**KPIs disponibles** :
```sql
-- Metrics quotidiennes
SELECT full_date, revenue, orders, avg_order_value, on_time_rate
FROM marts_analytics.mart_sales_daily
ORDER BY full_date DESC;

-- Trends avec MA
SELECT full_date, revenue, revenue_7d_ma
FROM marts_analytics.mart_sales_daily;
```

### Customer Retention

**Cohort Analysis** :
```sql
SELECT 
    cohort_label,
    months_since_cohort,
    retention_rate,
    cumulative_revenue_per_customer
FROM marts_analytics.mart_customer_cohorts
WHERE cohort_month >= '2017-01-01'
ORDER BY cohort_month, months_since_cohort;
```

### Marketing Campaigns

**Targeting High-Value At-Risk Customers** :
```sql
SELECT 
    customer_id,
    customer_state,
    historical_ltv,
    predicted_clv_12m,
    churn_risk,
    marketing_priority
FROM marts_analytics.mart_customer_lifetime_value
WHERE churn_risk IN ('High', 'Very High')
  AND predicted_clv_12m > 500
ORDER BY predicted_clv_12m DESC;
```

### Product Management

**Products needing attention** :
```sql
SELECT 
    category_name_en,
    product_id,
    revenue,
    product_health_score,
    product_recommendation
FROM marts_analytics.mart_product_performance
WHERE product_recommendation IN ('Consider Removal', 'Investigate Quality')
ORDER BY revenue DESC;
```

### Operations

**Delivery routes needing improvement** :
```sql
SELECT 
    customer_state,
    seller_region,
    on_time_rate,
    avg_delivery_days,
    performance_tier,
    recommendation
FROM marts_analytics.mart_delivery_kpis
WHERE performance_tier = 'Needs Improvement'
ORDER BY total_deliveries DESC;
```
